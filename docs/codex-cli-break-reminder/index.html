How to add a break reminder to Codex CLI

vibestretch installs in OpenAI Codex CLI from the plugin marketplace. It shows a stretch line and plays a chime during long turns.

Install as a plugin

codex plugin marketplace add Eliasjunit/vibestretch
codex plugin add vibestretch@vibestretch

Codex does not run a plugin's hooks until you review them. Open /hooks and trust the three vibestretch entries. Until then the plugin is installed but silent.

Install by hand

A clone and a config file do the same job:

git clone https://github.com/Eliasjunit/vibestretch ~/.codex/vibestretch
cp ~/.codex/vibestretch/hooks/codex-hooks.json ~/.codex/hooks.json

Already have a ~/.codex/hooks.json? Merge the three entries from ours into it. Do not overwrite yours. Codex asks you to trust a new hook config the first time it runs. That prompt is expected.

Pick one way. With the plugin and the hand-made entries both in place, every hook runs twice. If you installed by hand before 0.8.0, remove our entries from ~/.codex/hooks.json when you switch to the plugin.

What you get in Codex

You get the line in the session and the chime. There is no notification banner, because Codex has no hook output field for a terminal sequence. There is no status line segment either. That bar is not scriptable in Codex.

The counter is shared with Claude Code and Gemini CLI. An hour of waiting counts once, whichever agent kept you in the chair. The adapter was run on a live install of Codex CLI 0.149.1 on macOS.

FAQ

I installed it, but nothing happens. Why?
Codex runs a plugin's hooks only after you trust them. Open /hooks and trust the three vibestretch entries.
Every hook runs twice. Why?
You probably have both the plugin and hand-made entries in ~/.codex/hooks.json. Keep one of the two.
Can I use it with codex exec?
Set VIBESTRETCH_DISABLE=1 in that environment. Unattended runs should not count as time you sat through.
