Cómo añadir un recordatorio de pausas a Codex CLI

vibestretch se instala en OpenAI Codex CLI desde el marketplace de plugins. Muestra una línea de estiramiento y reproduce un tono durante los turnos largos.

Instalar como plugin

codex plugin marketplace add Eliasjunit/vibestretch
codex plugin add vibestretch@vibestretch

Codex no ejecuta los hooks de un plugin hasta que los revisas. Abre /hooks y marca como confiables las tres entradas de vibestretch. Hasta entonces, el plugin está instalado pero en silencio.

Instalar a mano

Un clon y un archivo de configuración hacen lo mismo:

git clone https://github.com/Eliasjunit/vibestretch ~/.codex/vibestretch
cp ~/.codex/vibestretch/hooks/codex-hooks.json ~/.codex/hooks.json

¿Ya tienes un ~/.codex/hooks.json? Combina en él las tres entradas del nuestro. No sobrescribas el tuyo. Codex te pide que confíes en una configuración de hooks nueva la primera vez que se ejecuta. Ese aviso es normal.

Elige un solo método. Si tienes a la vez el plugin y las entradas manuales, cada hook se ejecuta dos veces. Si lo instalaste a mano antes de la 0.8.0, quita nuestras entradas de ~/.codex/hooks.json cuando cambies al plugin.

Qué obtienes en Codex

Obtienes la línea en la sesión y el tono. No hay notificación, porque Codex no tiene un campo de salida de hook para una secuencia de terminal. Tampoco hay segmento en la línea de estado. Esa barra no se puede programar en Codex.

El contador se comparte con Claude Code y Gemini CLI. Una hora de espera cuenta una sola vez, sea cual sea el agente que te tuvo en la silla. El adaptador se probó en una instalación real de Codex CLI 0.149.1 en macOS.

Preguntas frecuentes

Lo instalé, pero no pasa nada. ¿Por qué?
Codex solo ejecuta los hooks de un plugin después de que confíes en ellos. Abre /hooks y marca como confiables las tres entradas de vibestretch.
Cada hook se ejecuta dos veces. ¿Por qué?
Probablemente tienes a la vez el plugin y entradas manuales en ~/.codex/hooks.json. Quédate con uno de los dos.
¿Puedo usarlo con codex exec?
Define VIBESTRETCH_DISABLE=1 en ese entorno. Las ejecuciones desatendidas no deberían contar como tiempo que pasaste esperando.
