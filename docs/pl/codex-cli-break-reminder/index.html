Jak dodać przypomnienie o przerwie do Codex CLI

vibestretch instaluje się w OpenAI Codex CLI z marketplace'u wtyczek. Podczas długich odpowiedzi pokazuje linię z ćwiczeniem i odtwarza dźwięk.

Instalacja jako wtyczka

codex plugin marketplace add Eliasjunit/vibestretch
codex plugin add vibestretch@vibestretch

Codex nie uruchamia hooków wtyczki, dopóki ich nie przejrzysz. Otwórz /hooks i oznacz trzy wpisy vibestretch jako zaufane. Do tego czasu wtyczka jest zainstalowana, ale milczy.

Instalacja ręczna

To samo robi klon repozytorium i plik konfiguracyjny:

git clone https://github.com/Eliasjunit/vibestretch ~/.codex/vibestretch
cp ~/.codex/vibestretch/hooks/codex-hooks.json ~/.codex/hooks.json

Masz już ~/.codex/hooks.json? Dopisz do niego trzy wpisy z naszego pliku. Nie nadpisuj swojego. Przy pierwszym uruchomieniu Codex poprosi o zaufanie nowej konfiguracji hooków. To normalne.

Wybierz jeden sposób. Jeśli masz jednocześnie wtyczkę i ręczne wpisy, każdy hook uruchamia się dwa razy. Jeśli instalowałeś ręcznie przed 0.8.0, usuń nasze wpisy z ~/.codex/hooks.json, gdy przechodzisz na wtyczkę.

Co działa w Codex

Dostajesz linię w sesji i dźwięk. Nie ma banera powiadomienia, bo Codex nie ma w wyjściu hooka pola na sekwencję terminala. Nie ma też segmentu paska stanu. Tego paska w Codex nie da się oskryptować.

Licznik jest wspólny z Claude Code i Gemini CLI. Godzina czekania liczy się raz, niezależnie od tego, który agent trzymał cię na krześle. Adapter uruchomiono na działającej instalacji Codex CLI 0.149.1 w macOS.

Najczęstsze pytania

Zainstalowałem, ale nic się nie dzieje. Dlaczego?
Codex uruchamia hooki wtyczki dopiero po oznaczeniu ich jako zaufane. Otwórz /hooks i zaufaj trzem wpisom vibestretch.
Każdy hook uruchamia się dwa razy. Dlaczego?
Prawdopodobnie masz i wtyczkę, i ręczne wpisy w ~/.codex/hooks.json. Zostaw jedno z nich.
Czy mogę używać go z codex exec?
Ustaw VIBESTRETCH_DISABLE=1 w tym środowisku. Uruchomienia bez twojego udziału nie powinny liczyć się jako czas, który przesiedziałeś.
